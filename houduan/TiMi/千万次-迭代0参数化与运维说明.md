## 1. 可配置参数（键名即 JSON/YAML 键）

| 键 | 类型 | 默认 | 含义 |
|---|---|---|---|
| StaticRewardRate | number | 0.13 | 静态收益率 |
| DynamicShardReward1GenerateRate / 3 / 5 | number | 0.015 / 0.02 / 0.025 | 一代/三代/五代动态分享 |
| TeamRewardRate1 / 2 / 3 | number | 0.005 / 0.01 / 0.015 | F1/F2/F3 团队伞下比例 |
| LossRate | number | 0.5 | 倒2/倒3 失败扣除比例（扣币折算算力） |
| FeeRate | number | 0.03 | 提币手续费率 |
| **FeeSymbol** | string | "TM" | 手续费币种（owner 2026-09-08 裁定按千万次第9条定稿 TM；N次方历史默认 BOFI 见 enum.FEE_SYMBOL，切回需 params 覆盖） |
| MinRound | number | 3 | 三进一出（N+3 口径，owner 2026-09-08 裁定）：第 N 轮结算第 N-MinRound 轮，即投第 N 轮在第 N+3 轮 End 结算 |
| MinTimeLimitSeconds | number | 600 | 轮次动态缩短的最小时限下限（秒） |
| F1DirectCount | number | 10 | F1 直推人数 |
| F1VoteCount | number | 30 | F1 伞下参投/成功人数 |
| F1ToF2Count / F2ToF3Count | number | 3 / 3 | F1→F2→F3 所需伞下等级人数 |
| MiningRewardBuff / MiningRewardSymbol / MiningWithdrawMinCount | number/string/number | 3 / FIBO / 50 | 矿机收益膨胀/币种/起提 |
| HashPowerBuff / HashPowerPoolDailyRatio / HashPowerMaxDays | number | 3 / 0.3 / 300 | 算力矿机三倍/矿池占比/保底天数 |
| BurnTarget | number | 7777 | 手续费销毁通缩目标（枚） |
| CurrentStage | number | 1 | 多阶段币种开关（1/2/3） |

编码约定：数值 **0**、字符串 **空串** 表示「未设置/不覆盖」（沿用默认值）。

生效优先级：**代码默认值 < config 表 params 列 < yml Params 段**。
各程序 main 在 `config.Init` 后调用 `impl.LoadNpowerParams()` 加载；`ops/params` 写入后热加载。

## 2. 运维接口（ops 服务，配置 `config/ops.yml`，默认端口 :5000）

1) 登录拿 token（与既有 ops 相同）：
```bash
curl -X POST http://127.0.0.1:5000/ops/sign -H 'Content-Type: application/json' \
  -d '{"account":"blx","pwd":"blxup2022city"}'
```
返回 token 后，以下接口带 `Authorization: Bearer <token>`。

2) 运行参数：
```bash
# 读取（config 表 params，未配置返回空对象）
curl http://127.0.0.1:5000/ops/params -H 'Authorization: Bearer <token>'

# 写入并热加载（键见 §1；0/空串字段不覆盖）
# 默认是**合并语义**：只覆盖 body 里出现的键，其余键保持不动（2026-09-30 修复）
curl -X POST http://127.0.0.1:5000/ops/params -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' -d '{"StaticRewardRate":0.13,"LossRate":0.5,"CurrentStage":1}'

# 删除某个键（合并语义下用 null；适用于"要把参数恢复成不存在"）
curl -X POST http://127.0.0.1:5000/ops/params -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' -d '{"FiboStaticPrice":null}'

# 整体替换（只保留 body 里的键，其余全部移除）——脚本式"备份-改-写回"请用这个
curl -X POST 'http://127.0.0.1:5000/ops/params?mode=replace' -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' -d '{"CurrentStage":2,"WithdrawSingleMax":-1}'
```
> ⚠ 2026-09-30 语义修复：原实现是**整体覆盖**（注释却写"0/空不覆盖"），
> 只传一个键会把库里的 `FeeSymbol/MinRound/CurrentStage` 等一起抹掉、静默回落代码默认值。
> 现在默认合并；`scripts/privchain-{rounds,hashpower,multiteam,withdraw-limits,f2f3}.ps1`
> 因为依赖"少一个键=删掉该参数"，已统一显式传 `?mode=replace`；
> `scripts/privchain-fix-verify.ps1` 的 [5] 段会同时校验两种语义。

```bash
# yml 写法（任意程序自己的 yml，启动级显式覆盖，优先级最高）
# Params:
#   StaticRewardRate: 0.13
#   FeeSymbol: "TM"
#   MinRound: 3
```

3) 算力矿机模式（0 默认三倍 / 1 最长300天三倍 / 2 TM加速）：
```bash
curl -X POST http://127.0.0.1:5000/ops/setHashPowerMode -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' -d '{"id":1,"mode":1}'
# 或按地址： -d '{"address":"Kto...","mode":2}'
```
说明：`mode` 写入 `hash_power.mode`，hashpower 定时产币（DailyReward）会按新模式保底/出局；mode1/2 的 4h 均价当前以 FIBO 实时价近似。用户侧"购买 TM 加速"未在本轮实现（运营先行）。

## 3. 手续费币种说明（FeeSymbol，owner 2026-09-08 定稿 TM）

- 当前默认 **TM**（千万次第9条：提币 3% 手续费用 TM 支付，销毁至 7777）。精度（SymbolDictionary TM=1e8）、图标、价格源（3.4U 静态兜底）、burn 销毁链路均已贯通 `impl.FeeSymbol`。
- 历史默认为 BOFI（enum.FEE_SYMBOL），如需切回或切其他币种：
  1. 通过 params 覆盖（config 表 params 列 JSON 或 yml Params 段写 FeeSymbol），热更新生效；
  2. 目标币种需补齐：`config.SymbolDictionary` 精度、`config.SymbolIconDictionary` 图标（可选）、`core/impl/price.go` 价格源（静态/行情）、链上销毁支持（`cmd/burn` 经 `kto.KTOonChainSync` 上链，确认目标币所在链与资金池）；
  3. 阶段 2/3 的允许币种列表会自动把原手续费币种替换为新币种（见 `impl.setFeeSymbol`）。

## 5. 复盘 Wave-2 资金安全修复（2026-09 复盘整改）
- `core/impl/vote.go`：投票改并发安全——锁内**重读**轮/余额后，轮进度用加法 UPDATE、余额用带 `amount>=?` 守卫的减法 UPDATE、投入记录加法累加；跨实例并发不丢更新、不超扣、不超募。
- `core/impl/reward.go`：新增 `claimSettleRound` 结算幂等抢占（Compute/Starting→Ending），Success/FailedNormal/Failed 三个结算事务内最先抢占，重复/并发结算直接跳过；失败回滚后可重试。
- `core/impl/round.go`：End 入口先抢占 Starting→Compute，防止同一轮被重复 End（尤其避免超级账号本金重复退还）。
- 遗留（下一批候选）：提币上链仍在 DB 事务内（链成功-DB失败的双花窗口）、24h 提币频控非原子、密钥/口令外置、跨进程参数热更等，见复盘报告。

## 6. 复盘 Wave-3/4：资金/运营/自动续轮收口
- **提币**（http/handler/wallet.go）：24h 频控原子化并收紧为 3 次/24h；手续费与本金扣减改"带 amount>=? 守卫的原子减法"；手续费币/被提币无报价时显式报错（不再 Inf/0 费率漏收）；GetCny 类型安全。
- **ops**：登录凭据 yml 可配（Ops.Account/Password，未配回退 blx/blxup2022city）；Mode=prod 时不注册 /ops/test/* 等测试/占位路由。
- **trshash /callback**：可选 Callback.Secret（请求头 X-Callback-Key 常时比较）；字段缺失/类型错误拒绝而非 panic；未配置密钥 Warn 一次。
- **参数热更**：ops/params 保存后向 Redis 频道 `npower:params:reload` 广播，npower/round/hashpower/burn/mining/demo 订阅后免重启生效（各 main 调 `impl.WatchNpowerParamsReload()`）。
- **自动续轮**：成功轮 End 后自动创建下一轮（target×1.3，min/max/时限沿用，幂等不重复建）→ 补齐"进入下一次循环"自动化。
- **TM 支持**：SymbolDictionary/SymbolIconDictionary 增加 TM(1e8，图标占位)；价格兜底 3.4U/枚；行情刷新失败不再缓存 0。
- **投入限额口径**：默认开启"每轮每用户累计投入 ≤ round.MaxVote"（TiMi需求#2）；参数 `MaxVoteIsPerUserRound`：1=保持开启，-1=显式关闭（退回"MaxVote 仅限单笔"存量口径），0/空=不覆盖。启用后 vote 事务内追加总和守卫。
- 仍有取舍（需产品/链上/运维配合，未静态落地）：提币"两段式(链上移出事务+回执确认+看门狗)"、密钥/口令外置与存量私钥轮换、注册 token 缩短+刷新、真实 4h 均价数据源、TM 用户购买/入账闭环、第三阶段币种。

## 7. 构建

- Windows 本地：`build-all.bat` → 产物输出到 **`build\`**（与 `start-local.bat` 及所有文档引用的路径一致）
- Linux amd64 交叉编译：`build-linux.bat`（可传单个程序名，如 `build-linux.bat round`）→ `build\linux\`
- **六个生产必需进程**：`npower` / `round`（结算器）/ `evmwatch`（EVM 充值监听）/ `hashpower`（每日产币）/ `burn` / `trshash`
- 本机无外网（依赖已随仓库落地）时先设置工作区缓存：
  ```powershell
  $r = "<仓库根>"
  $env:GOMODCACHE="$r\.gomodcache"; $env:GOCACHE="$r\.gocache"; $env:GOPATH="$r\.gopath"
  $env:GOFLAGS="-p=1"; $env:GOPROXY="off"
  ```
- ⚠ `.bat` 必须保持 **CRLF** 换行（cmd.exe 解析多行块与标签依赖 CRLF）；带中文提示的文件另需 UTF-8 BOM（配合 `chcp 65001`）
- 编译与单测自检：`go build ./...`（期望 exit 0）、`go test ./...`（期望全绿；连库集成用例需设 `NPOWER_TEST_CONFIG` 才执行，否则跳过）

## 8. 2026-09-30 新增/变更的配置项

| 配置 | 位置 | 说明 |
|---|---|---|
| `apiAuthKey` | yml 顶层 | /api 组鉴权（`X-API-Key`）。**`Mode=prod` 且为空时 npower 拒绝启动**；该 key 会随前端包下发，只用于挡扫描器 |
| `Mode` | yml 顶层 | `prod` 时启用配置体检（`apiAuthKey` 为空 / `secretKey` 仍是示例值 → 拒绝启动；检测到明文私钥打告警），ops 侧同时不注册 `/ops/test/*` |
| `Auth.EnforceSession` | yml `Auth` | 现在只决定**读接口**是否要求会话；**写接口（参投/提现/领取/切换算力）无论该值为何都要求钱包签名会话** |
| `Auth.AllowUnsignedWrite` | yml `Auth` | **仅联调**：允许无会话写请求沿用 body 地址（私链脚本用 SQL 造的无私钥账号需要它）。`Mode=prod` 时强制忽略 |
| `KtoPool.privateKeyEnv` / `TronPool.privateKeyEnv` / `BofiPool.privateKeyEnv` / `MinePool.privateKeyEnv` | yml 各池 | 私钥环境变量名；非空且该环境变量有值时优先于 `Private`（生产应只配环境变量，yml 留空） |
| `Burn.privateKeyEnv` | yml `Burn` | 销毁出资私钥的环境变量名（与 `Withdraw.HotWalletKeyEnv` 同口径） |
| 原生提现单笔上限 | `/ops/params` | 原先硬编码 `amount > 10000` 改不动；现在配了 `WithdrawSingleMax` 即以配置为准，未配才回落 10000 兜底 |
