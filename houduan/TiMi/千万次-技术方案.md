## 一、需求理解：千万次玩法规则结构化

### 1.1 众筹轮次模型（核心三要素）

| 要素 | 规则 |
|---|---|
| 总额度 | 每轮固定递增 **30%**（第一轮基数可配置，如 1000 / 5000） |
| 时间 | 每轮时限（基础 1h，按市场活跃度动态调整，可 30min / 10min，下限 600s） |
| 参与额度 | 最低限额不变，最高限额每轮小幅递增；**每轮可多次投入、无次数上限** |

示例（基数 1000，最高限额递增）：第1轮 1000/1h/10-100 → 第2轮 1300/1h/10-110 → 第3轮 1690/1h/10-130 → 第4轮 2197/1h/10-150。

### 1.2 静态收益：13% + 三进一出

- 每轮**成功**，该轮参与者获得 **13% 静态收益**（连本带息可继续复投）；
- **三进一出**（规则来源：N次方，千万次未另行规定）：第 N 轮投入的资金，在第 **N+3** 轮结束时统一结算（无论第 N+3 轮成败），本息秒到；
- 实现：`rewardRoundNum = currentRound - MinRound`，**MinRound=3**（owner 2026-09-08 裁定，原实现 MinRound=2 为 N+2 已修正）；
- 轮次无上限，直到某一轮未筹满 → 触发失败结算 → 进入下一期循环。

### 1.3 失败结算：倒1 / 倒2 / 倒3

| 轮次 | 处理 |
|---|---|
| 倒1（失败轮，当前轮） | **100% 退还本金**，无损失 |
| 倒2 / 倒3 | **扣除 50% 币**；被扣部分按实时价格（U 计价）**折算为算力**进入矿机挖矿，直到 3 倍出局 |
| 更早轮次 | 已结算（三进一出已出局） |

### 1.4 动态收益（分享收益，按直推人数解锁层级）

| 直推人数 | 收益层级 |
|---|---|
| ≥2 | 第一代 1.5% |
| ≥5 | 第一代 1.5% + 第三代 2% |
| ≥10 | 第一代 1.5% + 第三代 2% + 第五代 2.5% |

注意：收益层级按**直推人数**解锁，伞下延伸再多也不替代直推人数。

### 1.5 团队收益（F1 / F2 / F3，按伞下总投资额比例）

| 等级 | 伞下总投资额比例 |
|---|---|
| F1 | 0.5% |
| F2 | 1% |
| F3 | 1.5% |

晋升条件：**F1** = 直推 10 地址 + 伞下 30 人参与某一期 + 伞下 30 人各成功至少 1 次（口径：历史累计，任意期任意成功轮）；**F2** = 伞下 3 个 F1；**F3** = 伞下 3 个 F2。

### 1.6 算力矿机（爆仓补偿）

- 被扣 50% 币 → 按爆仓时币价折算算力：`算力 = 扣除数量 × 币价(U)`；
- 三种模式：
  1. **默认三倍出局**：累计币量 × 4h 均价，日产出 = 每日区块总产出 × 0.3（可产 73 年）；
  2. **最长 300 天三倍出局**：保底每日产出 = `(算力×3) / 300 / 4h均价`；
  3. **TM 兑换**（3.4U/枚）：300 天三倍出局；
- "三倍"按**金本位**（币价上涨更快回本）。

### 1.7 手续费（已定稿）

- 提币 **3% 手续费**，手续费币种 = **TM**（owner 裁定按千万次第9条；提价值 100U 的币需 3U 价值的 TM 支付）；
- 所有手续费**链上销毁**，直至 **TM 仅剩 7777 枚**（通缩设计）。

### 1.8 多阶段多币种

- 第一阶段：FIBO + USDT；第二阶段：+ 手续费币（TM）+ KTO；第三阶段：更多 Token。

## 三、技术方案（实施态）

### 3.1 总体架构

```
┌─────────────────────────────────────────────────────────┐
│  程序层                                                  │
│  npower 主服务(:3000) │ round 轮定时器 │ trshash 充值监听 │
│  collecting 归集 │ ops 运维(:5000) │ burn 手续费销毁     │
│  mining 矿机产出 │ hashpower 算力 │ manual 手动归集      │
│  demo 演示网关(:3001, 仅本地)                            │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│  核心业务层（core/impl）                                  │
│  OnBoarding 钱包 │ Rounding 轮次 │ Voting 投入           │
│  Rewarding 结算(团队伞下比例/爆仓算力) │ HashPower 算力   │
│  Price 价格(TM=3.4U 兜底) │ Params 运行参数(热更新)      │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌───────────────┬─────────────────────────────────────────┐
│ MySQL(15表+hash_power+fee_burn) │ Redis(token/锁/队列/参数广播) │
└───────────────┴─────────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│  外部链：FIBO │ USDT/TRON │ KTO │ 手续费销毁(burn/黑洞)  │
└─────────────────────────────────────────────────────────┘
```

### 3.2 数据模型

17 张表：15 张复用 + `hash_power`（爆仓算力账户）+ `fee_burn`（手续费销毁记录），DDL 见 [N次方-技术方案-历史参考.md](./N次方-技术方案-历史参考.md) 3.2 节（与现网一致）。

**config 表扩展**：`params` 列（JSON，运行参数，含 FeeSymbol=TM、MinRound=3、BurnTarget=7777、CurrentStage 等），生效优先级 **代码默认 < config 表 params < yml Params 段**，运维改参免重启。

### 3.3 核心流程（实施态）

#### 流程1：众筹循环
```
ops 开期 → round 定时开始轮（每2s扫描 status=0 且 start 已过1m15s）
  → 用户多次投入 → 到期 round.End（每整分钟0秒扫描 status=1 且 end 已过）
  ├─ 成功(CurrentVote ≥ TargetVote)
  │    ├─ Promote 等级晋升（F1 三条件）
  │    ├─ 结算第 (currentRound-3) 轮：静态13% + 动态分享 + 团队伞下比例 + 退本
  │    │   （rewardRound 需处于 status=2 待结算，结算失败整轮回滚不静默漏发）
  │    └─ 开下一轮（额度×1.3）
  └─ 失败(未筹满)
       ├─ 倒1：FailedNormal（100% 退本）
       ├─ 倒2/倒3：Failed（扣50% → 折算算力入 hash_power，DailyReward 保底按 FIBO 价）
       └─ 项目停止 → 进入下一期
```

#### 流程2：算力矿机产币
```
每日：矿池日产出 = FIBO 每日区块产出×0.3 → 按算力占比分配
  → 保底：模式2/3 按 (算力×3)/300/4h均价
  → 累计达三倍目标(金本位) → status=1 出局可提取
```

#### 流程3：手续费销毁
```
提币扣 3%（impl.FeeSymbol=TM）→ fee_burn 待销毁
  → burn 定时：原子抢占 status=3(销毁中) → 链上 burn → 成功置1记hash，失败置2重试
  → 监控 TM 流通量至 7777
```

### 3.4 关键算法

| 算法 | 公式 | 状态 |
|---|---|---|
| 轮次目标递增 | `target_n = round(target_{n-1} × 1.3)` | ✅ |
| 静态收益 | `vote.Amount × 13%` | ✅ 已验证（+113 含本金实测） |
| 三进一出 | `rewardRoundNum = currentRound - MinRound(3)` | ✅ 已验证（第3轮在第5轮结算） |
| 动态分享 | 一代×1.5%、三代×2%、五代×2.5%，直推 2/5/10 解锁 | ✅ |
| 团队收益 | `Σ(伞下该期投资额) × 0.5%/1%/1.5%`（F1/F2/F3） | ✅ |
| 爆仓算力 | `power = 扣除数量(50%) × 爆仓时币价(U)` | ✅ |
| 三倍目标 | `target_reward(币) = power × 3 / 出局时币价`（金本位） | ✅ |
| 保底日产出 | `(power × 3) / 300 / 4h均价` | ✅ |
| 手续费 | `提现额(折U) × 3% / TM价(3.4U)` | ✅ 已验证（TM 扣费/BOFI 拒绝） |

### 3.5 安全与并发

- 余额并发：`WalletPointSafe.AddPointAmount` 乐观锁 CAS；
- 投入串行：`VoteManager.Lock`；
- 充值幂等：redislock + hash 去重；
- 算力扣减原子：`UPDATE ... WHERE remain_reward >= cut`（RowsAffected=0 返回冲突，防超发）；
- burn 幂等：status 原子抢占，防重复销毁；
- 结算可靠性：calcTeamReward 失败整轮回滚（轮留待结算状态自动重试）；
- 单设备登录：JWT + Redis；报文加密：RSA + AES（pem 文件化）；
- 闭包表：偏移约定 distance=0 即直推，三条建边路径统一，查询端四处排除自身行防御。
