## 1. 交付物

⚠ 2026-09-30 更正：原清单只交付 `npower` + `burn`，并把 `round` 归为"本地调试工具"。
但 `round` 是**唯一结算器**（开轮/结束轮/三进一出结算/结算补偿巡检），`evmwatch` 是**唯一
EVM(TM) 充值监听**、`hashpower` 是**唯一每日产币**、`trshash` 是 KTO/TRON 充值监听——
不部署它们，用户充值不到账、轮次不结束、爆仓算力不产出，业务整体停摆。

| 产物 | 说明 | 生产必需 | 生成方式 |
|---|---|---|---|
| `build/linux/npower` | 主服务（HTTP + /api 适配层，首启 AutoMigrate 自动建表） | ✅ | `build-linux.bat npower` |
| `build/linux/round` | **轮次结算器**：开轮、结束轮、三进一出结算、结算补偿巡检 | ✅ | `build-linux.bat round` |
| `build/linux/evmwatch` | **EVM(TM) 充值监听**：扫链 → 确认数 → 幂等入账 | ✅ | `build-linux.bat evmwatch` |
| `build/linux/hashpower` | **每日算力产币**（爆仓折算算力的产出，含保底与出局判定） | ✅ | `build-linux.bat hashpower` |
| `build/linux/burn` | 手续费链上销毁（TM 通缩至 7777） | ✅ | `build-linux.bat burn` |
| `build/linux/trshash` | KTO/TRON 充值监听（非 EVM 阶段/币种时必需） | 视阶段 | `build-linux.bat trshash` |
| `build/linux/ops` | 运维后台(:5000)：改参/开轮/风控名单/审计 | 建议 | `build-linux.bat ops` |
| `build/linux/recon` | 对账巡检（只读，退出码 0/1/2 供监控告警） | 建议 | `build-linux.bat recon` |
| `config/etc.production.yml` | 生产配置（**权限 600，不入库**） | ✅ | 由 `config/etc.yml` 复制后逐项修改 |

编译参数：`GOOS=linux GOARCH=amd64 CGO_ENABLED=0 -trimpath -ldflags "-s -w"`（静态无 glibc 依赖）。
`build-linux.bat` 一次性产出上述全部二进制（不传参 = 全部；传程序名 = 单个）。
本机无外网时先 `set GOMODCACHE=<仓库根>\.gomodcache`、`set GOCACHE=<仓库根>\.gocache`、
`set GOFLAGS=-p=1`、`set GOPROXY=off`（依赖已随仓库落地）。

## 2. 服务器规划（Ubuntu 22.04）

```
/opt/qianwanci/
├── bin/npower bin/round bin/evmwatch bin/hashpower bin/burn bin/trshash [bin/ops bin/recon]
├── config/etc.production.yml   # 生产配置（权限 600，且**不含明文私钥**，见 §3）
├── config/secrets.env          # 私钥环境变量（权限 600，chown qwt）
├── logs/                       # 应用日志（journald 为主，此目录兜底）
└── backups/                    # 配置备份

专用运行用户：qwt（禁止 root 跑服务）
MySQL：8.0+，库 qianwanci，专用最小权限用户
Redis：生产必须设 requirepass，且与其他业务分库
```

各进程的常驻方式见 §6；**六个进程缺一不可**（npower / round / evmwatch / hashpower / burn / trshash），
建议全部用 systemd 管理并配 `Restart=on-failure`。

## 3. 配置准备与密钥分离核查

复制 `config/etc.yml` 为 `etc.production.yml`，逐项核查：

| 配置项 | 生产要求 | 风险等级 |
|---|---|---|
| `HttpPort` | `":3000"`（仅监听本机，由 Nginx 反代对外） | 中 |
| `Mode` | **必须 `prod`**：npower 启动即做配置体检（`apiAuthKey` 为空 / `secretKey` 仍是示例值 → **拒绝启动**）；ops 侧同时不注册 `/ops/test/*` | 🔴 高 |
| `apiAuthKey` | **必须设置强随机值**（≥32 位）。⚠ 该 key 会随前端包下发，只能挡扫描器；用户身份靠钱包签名会话 | 🔴 高 |
| `secretKey` | 生产专用新值，禁止沿用仓库里的 `dsajflkadsjglafsdj` / `privchain-local-secret`（体检会拒绝启动） | 🔴 高 |
| MySQL DSN | 指向专用库 + 最小权限用户（§4），禁用 root | 🔴 高 |
| `Chain.*` | 链 RPC / chainId / TM 合约地址 / `Confirmations` 与目标链一致 | 🔴 高 |
| `Chain.WatchPool` / `WatchToken` / `DepositCreditTo` | 充值监听口径：`sender`=共享收款池按付款方入账（DApp 口径） | 🔴 高 |
| `Chain.WatchStartBlock` | **上线必填**：充值监听起始块（建议=TM 合约部署高度）。⚠ 为 0 且未传 `-fromBlock` 时 evmwatch **拒绝启动**（fail-closed），防止"上线前的充值永远不入账" | 🔴 高 |
| `Chain.AllowStartFromLatest` | 生产必须 `false`；`true` 仅联调（表示接受不补扫历史充值） | 🔴 高 |
| `Http.ProxyHeader` + `Http.TrustedProxies` | 经 Nginx 反代时填 `X-Forwarded-For` + `["127.0.0.1"]`，否则限流退化成"全局单桶"。**两者必须同时配**（只配前者会被忽略并告警，避免伪造 XFF 绕过限流） | 中 |
| `NPOWER_AES_SECRET_KEY`（环境变量，非 yml） | 用户私钥落库口令（AES，16/24/32 位）。**新部署在写入任何用户数据前设定**；已上线环境更换会导致既有 `wallet.sign` 解不开，必须先做"旧口令解密→新口令重加密"迁移 | 🔴 高 |
| `Withdraw.Mode` / `ChainAsset` | `broadcast` 才上链；**必须显式列出允许出金的资产**，未列出的资产一律拒绝 | 🔴 高 |
| `Withdraw.HotWalletKeyEnv` | 热钱包私钥改由环境变量注入（yml 留空） | 🔴 高 |
| `KtoPool.privateKeyEnv` / `TronPool.privateKeyEnv` / `Burn.privateKeyEnv` | 资金池/销毁私钥改由环境变量注入（yml 留空） | 🔴 高 |
| `Auth.EnforceSession` | 建议 `true`（读接口也要求会话票）；**写接口无论该值为何都强制要求会话** | 中 |
| `Auth.AllowUnsignedWrite` | **生产必须为 false / 不配置**（true 只给私链脚本用；`Mode=prod` 时该开关被强制忽略） | 🔴 高 |
| `FeeSymbol` | 默认 TM；如需覆盖走 params（见迭代0 手册 §3） | 低 |
| `MinRound` | 3（三进一出 N+3 口径，owner 2026-09-08 裁定） | 低 |
| `Ops.Account` / `Ops.Password` | 必须显式配置强口令（未配置即禁用登录，fail-closed） | 🔴 高 |
| `/ops/params` 写入语义 | 默认**合并**（只改传入的键，`null`=删键）；脚本式"全量替换"请显式 `POST /ops/params?mode=replace`。⚠ 不要再用"只传一个键"的写法做整体替换 | 中 |
| 构建与自检入口 | 根目录 `Makefile`：`make check`（后端 build/vet/test）、`make bintest`（Linux 静态产物）、`make frontend`（前端单测+构建）；CI 见 `.github/workflows/ci.yml` | 低 |

### 3.1 密钥纪律（2026-09-30 审计后强化）

**现状（必须处理）**：仓库里的 `config/etc.yml`、`etc.local.yml`、`burn.yml`、`collecting.yml`、
`demo.local.yml` 等**被 git 跟踪的配置文件内含明文私钥/口令**（KTO/TRON/KBO 资金池私钥、
JWT 签名用的 `secretKey`、运维口令、`crypto/private.pem`），且已进入 git 历史。

处置步骤（缺一不可）：

1. **视为已泄露并轮换**：把这些地址上的资产全部转移到新生成的私钥；
2. **改为环境变量注入**：`/opt/qianwanci/config/secrets.env`（`chmod 600`、`chown qwt`）写
   `KTO_POOL_PRIVATE_KEY=` / `TRON_POOL_PRIVATE_KEY=` / `BURN_EVM_PRIVATE_KEY=` / `HOT_WALLET_PRIVATE_KEY=`
   （变量名与 yml 里 `privateKeyEnv` 的值一致），yml 里对应的 `Private` 字段留空；
3. systemd 单元用 `EnvironmentFile=` 引入（见 §6）；
4. **清理 git 历史**（加 remote / push 之前必须做）：`git filter-repo --path houduan/TiMi/config --path houduan/TiMi/crypto --invert-paths`
   或轮换后重建仓库；只删 HEAD 里的文件不清历史等于没做；
5. 生产配置与密钥文件只存服务器本地；不进 git、不进聊天/工单；泄露即轮换。

```bash
chmod 600 /opt/qianwanci/config/etc.production.yml /opt/qianwanci/config/secrets.env
chown -R qwt:qwt /opt/qianwanci
```

#### 3.1.0 两个脚本（已在本机验证，可直接用）

| 脚本 | 作用 | 验证情况 |
|---|---|---|
| `scripts/export-secrets.ps1` | 把 yml 里的明文私钥导出到**未跟踪**的 `config/secrets*.env`，并把 yml 改成 `privateKeyEnv` 环境变量注入（幂等；含 `-DryRun`） | 已执行：全仓库 `git grep` 无明文私钥字段；本地栈用注入的环境变量正常启动 |
| `scripts/purge-git-history.ps1` | 清历史（重建仓库模式）：门禁扫描 → 旧 `.git` 移到**工作区之外**备份 → 重建 + 提交 → 校验；失败自动回滚 | 已在克隆上完整演练并独立复核：清理后 KTO/TRON 私钥在 `git log --all -p` 里均搜不到 |

> ⚠ 顺序不能颠倒：**先转资产 → 再换密钥 → 最后清历史**。密钥已经进过 git 历史就必须视为已泄漏，
> 只清历史等于自我安慰（拿到过仓库的人仍能用旧私钥动那些地址）。
#### 3.1.1 轮换 + 历史清理操作手册（owner 执行；本仓库无 remote，风险可控）

> 为什么必须做：这些私钥**已经进入 git 历史**，只删 HEAD 里的明文没有意义（任何拿到仓库的人
> 都能从历史里翻出来）。而"视为已泄露"意味着**先转资产、再改配置**，顺序不能反。

**步骤 0：先确认影响面**（只读，可随时执行）

```bash
# 列出所有仍含明文私钥/口令的跟踪文件
git grep -nE '^\s*(Private|EvmPrivate|HotWalletPrivate)\s*:' -- houduan/TiMi/config
git grep -nE '(secretKey|apiAuthKey)\s*:' -- houduan/TiMi/config
```

**步骤 1：生成新密钥并转资产**（每个地址都要做，别漏）

| 旧密钥位置 | 对应资产/用途 | 动作 |
|---|---|---|
| `etc.yml: KtoPool.Private` | KTO 资金池（用户充值/提现地址） | 生成新 KTO 账户 → 把余额转过去 → 更新 `KTO_POOL_PRIVATE_KEY` |
| `etc.yml: TronPool.Private` | TRON 资金池 | 同上（TRON 侧） |
| `burn.yml: Burn.EvmPrivate` / `etc.yml: Burn` | 手续费销毁出资地址 | 注意：销毁由该地址**持有 TM**，换地址要先把 TM 转过去 |
| `Withdraw.HotWalletPrivateKey` | 出金热钱包 | 生成新地址 → 从资金池补足 TM → 更新 `HOT_WALLET_PRIVATE_KEY` |
| `etc.yml: SecretKey` | JWT 签名（不涉资金） | 直接换随机值；**换后所有已发出的会话票失效**（用户需重新签名登录） |
| `Ops.Password` | 运维后台口令 | 直接换强随机值 |
| `crypto/private.pem` / `public.pem` | 与客户端通信的 RSA 密钥对 | 需与前端发布同步换（`crypto` 目录的密钥由 DApp 侧使用，换前确认客户端版本） |
| `NPOWER_AES_SECRET_KEY`（新增） | 库内用户私钥 `wallet.sign` 的加密口令 | ⚠ **不能直接换**：库内既有密文会解不开。需先做"旧口令解密 → 新口令重加密"迁移后再切换 |

**步骤 2：改配置为环境变量注入**

```bash
install -m 600 /dev/null /opt/qianwanci/config/secrets.env
cat >/opt/qianwanci/config/secrets.env <<'EOF'
KTO_POOL_PRIVATE_KEY=<新值>
TRON_POOL_PRIVATE_KEY=<新值>
BURN_EVM_PRIVATE_KEY=<新值>
HOT_WALLET_PRIVATE_KEY=<新值>
NPOWER_AES_SECRET_KEY=<16/24/32 位；新部署直接设，老库需先迁移>
EOF
# yml 里对应 Private 字段清空，privateKeyEnv 指向上述变量名
```

**步骤 3：清理 git 历史**（二选一）


## 6. systemd 服务单元

**六个进程都要常驻**（npower / round / evmwatch / hashpower / burn / trshash），否则用户充值不到账、
轮次不结束、算力不产出、手续费不销毁。逐个创建单元文件（可复制同一模板改 `Description` 与 `ExecStart`）：

| 单元 | ExecStart（`-f` 指向同一份生产配置） | 作用 |
|---|---|---|
| `qianwanci.service` | `bin/npower -f config/etc.production.yml` | 主服务 :3000 |
| `qianwanci-round.service` | `bin/round -f config/etc.production.yml` | 开轮/结束轮/三进一出结算/结算补偿巡检 |
| `qianwanci-evmwatch.service` | `bin/evmwatch -f config/etc.production.yml` | EVM(TM) 充值监听（建议加 `-fromBlock <上线高度>`） |
| `qianwanci-hashpower.service` | `bin/hashpower -f config/etc.production.yml` | 每日算力产币 |
| `qianwanci-burn.service` | `bin/burn -f config/etc.production.yml` | 手续费链上销毁 |
| `qianwanci-trshash.service` | `bin/trshash -f config/etc.production.yml` | KTO/TRON 充值监听（非 EVM 阶段必需） |

模板（以主服务为例；`round`/`evmwatch` 等只需替换 `Description` 与 `ExecStart`）：

```ini
[Unit]
Description=Qianwanci (TiMi) main service
After=network-online.target mysql.service redis.service
Wants=network-online.target

[Service]
Type=simple
User=qwt
WorkingDirectory=/opt/qianwanci
EnvironmentFile=/opt/qianwanci/config/secrets.env
ExecStart=/opt/qianwanci/bin/npower -f /opt/qianwanci/config/etc.production.yml
Restart=on-failure
RestartSec=5
LimitNOFILE=65535
# 日志走 journald
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now qianwanci
journalctl -u qianwanci -f          # 观察首启 AutoMigrate 与监听日志
```

## 7. Nginx 反代（对外 443）

```nginx
server {
    listen 443 ssl;
    server_name api.<你的域名>;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

注意：
- 应用自带 /api 鉴权（X-API-Key 头），Nginx 层建议再加 IP 白名单或限速（`limit_req`）双层防护。
- HTTPS 证书用 certbot 签发；80 端口仅做 301 跳转。
- 直接暴露 3000 端口 = 放弃反代层防护，不推荐。

## 9. 上线检查清单

| # | 检查项 | 命令/方法 | 预期 |
|---|---|---|---|
| 1 | 六个进程存活 | `systemctl status qianwanci{,-round,-evmwatch,-hashpower,-burn,-trshash}` | 全部 active (running) |
| 2 | 无 key 访问被拒 | `curl -s https://域名/api/prices` | `{"code":600,"message":"未授权"}` |

## 10. 回滚方案

- 保留上一版二进制：部署新版本前 `cp bin/npower bin/npower.bak.$(date +%Y%m%d)`（其余进程同理）
- 回滚 = 停服务 → 换回二进制 → 起服务（配置不动，分钟级）
- DB 变更由 AutoMigrate 增量进行，回滚旧二进制通常兼容；若涉及破坏性变更，先备份库再操作
- ⚠ 本次修复改变了结算口径（倒2/倒3 现在会退还 50%），回滚到修复前的二进制会恢复"只扣不退"的行为，
  新旧二进制并存期间同一轮只能由一个版本结算（靠 `claimSettleRound` 抢占），但**不要**在结算高峰回滚
