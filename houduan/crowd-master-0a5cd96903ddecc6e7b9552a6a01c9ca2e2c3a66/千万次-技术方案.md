## 一、需求理解：千万次玩法规则结构化

### 1.1 众筹轮次模型（核心三要素）

| 要素 | 规则 |
|---|---|
| 总额度 | 每轮固定递增 **30%**（第一轮基数可配置，如 1000 / 5000） |
| 时间 | 每轮时限（基础 1h，按市场活跃度动态调整，可 30min / 10min） |
| 参与额度 | 最低限额不变，最高限额每轮小幅递增；**每轮可多次投入、无次数上限** |

示例（基数 1000，最高限额递增）：第1轮 1000/1h/10-100 → 第2轮 1300/1h/10-110 → 第3轮 1690/1h/10-130 → 第4轮 2197/1h/10-150。

### 1.2 静态收益：13% + 三进一出

- 每轮**成功**，该轮参与者获得 **13% 静态收益**（连本带息可继续复投）；
- **三进一出**：第 N 轮投入的资金，在第 N+3 轮结束时统一结算（无论第 N+3 轮成败），本息秒到；
- 轮次无上限，直到某一轮未筹满 → 触发失败结算 → 进入下一期循环。

### 1.3 失败结算：倒1 / 倒2 / 倒3

| 轮次 | 处理 |
|---|---|
| 倒1（失败轮，当前轮） | **100% 退还本金**，无损失 |
| 倒2 / 倒3 | **扣除 50% 币**；被扣部分按实时价格（U 计价）**折算为算力**进入矿机挖矿，直到 3 倍出局 |
| 更早轮次 | 已结算（三进一出已出局） |

### 1.4 动态收益（分享收益，按直推人数解锁层级）

| 直推人数 | 收益层级 |
|---|---|
| ≥2 | 第一代 1.5% |
| ≥5 | 第一代 1.5% + 第三代 2% |
| ≥10 | 第一代 1.5% + 第三代 2% + 第五代 2.5% |

注意：收益层级按**直推人数**解锁，伞下延伸再多也不替代直推人数。

### 1.5 团队收益（F1 / F2 / F3，按伞下总投资额比例）

| 等级 | 伞下总投资额比例 |
|---|---|
| F1 | 0.5% |
| F2 | 1% |
| F3 | 1.5% |

晋升条件：**F1** = 直推 10 地址 + 伞下 30 人参与某一期 + 伞下 30 人各成功至少 1 次；**F2** = 伞下 3 个 F1；**F3** = 伞下 3 个 F2。

### 1.6 算力矿机（爆仓补偿）

- 被扣 50% 币 → 按爆仓时币价折算算力：`算力 = 扣除数量 × 币价(U)`；
- 三种模式：
  1. **默认三倍出局**：累计币量 × 4h 均价，日产出 = 每日区块总产出 × 0.3（可产 73 年）；
  2. **最长 300 天三倍出局**：保底每日产出 = `(算力×3) / 300 / 4h均价`；
  3. **TM 兑换**（暂定 3.4U/枚）：300 天三倍出局；
- "三倍"按**金本位**（币价上涨更快回本）。

### 1.7 手续费

- 提币 **3% 手续费**，以手续费币种支付（TiMi 基准第 9 条：手续费代币 = TM，前端已裁决①（2026-09-04），实现按可配置处理）；
- 所有手续费**链上销毁**，直至 TM 仅剩 7777 枚（通缩设计，与 N次方 BOFI 销毁口径一致）。

### 1.8 多阶段多币种

- 第一阶段：FIBO + USDT（前端 SUPPORTED_ASSETS 已落地）；第二阶段：+ TM + KTO（按 TiMi 路线与产品确认）；第三阶段：更多 Token。

## 二、可行性分析

### 2.1 总体结论

**高度可行，预计 70%~80% 代码可直接复用。** crowd-master 与千万次是同构的"期-轮众筹 + 静态/动态收益 + 团队等级 + 爆仓补偿 + 手续费"玩法，Npower 已实现千万次约 80% 的核心机制（含"三进一出"结算），剩余差异集中在：团队收益计算方式、爆仓补偿形式（FUSD 积分 → 算力矿机）、手续费销毁、多阶段币种开关。

### 3.2 数据模型设计

**复用现有表**（15 张，字段基本不动）：project / project_round / vote / vote_reward / wallet / wallet_point / wallet_tx / wallet_hash_charge / wallet_tree / mining / mining_exchange / mining_exchange_reward / mine_machine / notify / config。

**新增 2 张表**：

```sql
-- 算力矿机账户（爆仓折算 + 挖矿出局）
CREATE TABLE hash_power (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  address       VARCHAR(64)  NOT NULL COMMENT '钱包地址',
  symbol        VARCHAR(16)  NOT NULL COMMENT '被扣代币（算力基准币）',
  power         DECIMAL(30,8) NOT NULL COMMENT '算力值 = 扣除数量×爆仓价(U)',
  price         DECIMAL(30,8) NOT NULL COMMENT '爆仓时币价(U)',
  mode          TINYINT      NOT NULL DEFAULT 0 COMMENT '0默认三倍 1最长300天 2TM兑换',
  total_reward  DECIMAL(30,8) NOT NULL DEFAULT 0 COMMENT '累计产出(币本位)',
  remain_reward DECIMAL(30,8) NOT NULL DEFAULT 0 COMMENT '剩余可提',
  target_reward DECIMAL(30,8) NOT NULL DEFAULT 0 COMMENT '三倍目标(金本位折算)',
  status        TINYINT      NOT NULL DEFAULT 0 COMMENT '0挖矿中 1已出局',
  start_time    DATETIME     NOT NULL COMMENT '入账时间',
  finish_time   DATETIME     NULL     COMMENT '出局时间',
  created_at    DATETIME     NULL, updated_at DATETIME NULL, deleted_at DATETIME NULL,
  KEY idx_addr (address), KEY idx_status (status)
) COMMENT='爆仓算力矿机账户';

-- 手续费销毁记录
CREATE TABLE fee_burn (
  id         BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  symbol     VARCHAR(16) NOT NULL COMMENT '手续费币种',
  amount     BIGINT      NOT NULL COMMENT '销毁数量(最小单位)',
  tx_hash    VARCHAR(96) NOT NULL COMMENT '链上销毁交易hash',
  status     TINYINT     NOT NULL DEFAULT 0 COMMENT '0待销毁 1已销毁 2失败',
  created_at DATETIME    NULL, updated_at DATETIME NULL, deleted_at DATETIME NULL,
  UNIQUE KEY uk_hash (tx_hash)
) COMMENT='手续费销毁记录';
```

**config 表扩展**：增加阶段配置（JSON 或独立键）：`stage`（当前阶段）、`stage_symbols`（阶段可参与币种）、`burn_target`（销毁目标 7777）、`fee_symbol`（手续费币种）、`round_increase_rate`（30%）、`static_rate`（13%）、`dynamic_rates`、`team_rates`、`hash_power_modes` 等，全部参数化，避免硬编码。

### 3.3 核心流程设计

#### 流程1：众筹循环（复用，微调）
```
ops 开期 → round 定时开始轮 → 用户多次投入 → 到期 round.End
  ├─ 成功(CurrentVote ≥ TargetVote)
  │    ├─ 提升参与者等级 Promote（F1/F2/F3）
  │    ├─ 结算第 (currentRound-2) 轮：静态13% + 动态分享 + 团队伞下比例 + 退本
  │    └─ 开下一轮（额度×1.3）
  └─ 失败(未筹满)
       ├─ 倒1：FailedNormal（100% 退本）
       ├─ 倒2/倒3：Failed（扣50% → 折算算力入 hash_power）
       └─ 项目停止 → 进入下一期
```

#### 流程2：算力矿机产币（新增定时任务，并入 round 或独立）
```
每日（或每区块窗口）：
  1. 读取 FIBO 每日区块产出×0.3 作为矿池日产出
  2. 按各 hash_power 账户算力占比分配
  3. 保底逻辑：模式1(默认)按累计量；模式2/3 按 (算力×3)/300/4h均价
  4. 累计产出达到 三倍目标(金本位) → status=1 出局，可提取
```

#### 流程3：手续费销毁（新增 burn 程序）
```
提币扣 3% 手续费(手续费币种) → 汇总入销毁池(fee_burn 待销毁)
  → burn 定时任务：批量调链上 burn/转黑洞地址 → 记 tx_hash → 监控流通量至 7777
```

### 3.4 关键算法

| 算法 | 公式 |
|---|---|
| 轮次目标递增 | `target_n = round(target_{n-1} × 1.3)`（已实现） |
| 静态收益 | `vote.Amount × 13%`（已实现） |
| 动态分享 | 一代 `×1.5%`、三代 `×2%`、五代 `×2.5%`，按直推人数解锁（已实现） |
| 团队收益（重写） | 对每个 F1/F2/F3：`Σ(伞下用户该期投资额) × 0.5%/1%/1.5%` |
| 爆仓算力 | `power = 扣除数量(50%) × 爆仓时币价(U)` |
| 三倍目标 | `target_reward(币) = power × 3 / 出局时币价`（金本位） |
| 保底日产出 | `(power × 3) / 300 / 4h均价` |
| 手续费 | `提现额(折U) × 3% / 手续费币价`（已实现，改币种可配） |

### 3.5 安全与并发（复用现有机制）

- 余额并发：`WalletPointSafe.AddPointAmount` 乐观锁 CAS（复用）；
- 投入串行：`VoteManager.Lock`（复用）；
- 充值幂等：redislock + hash 去重（复用）；
- 算力账户并发：hash_power 入账/产出同样走乐观锁或 redislock（新增实现沿用同模式）；
- 单设备登录：JWT + Redis（复用）；
- 报文加密：RSA + AES（复用）。

## 五、风险与注意事项

| 风险 | 等级 | 说明与对策 |
|---|---|---|
| 团队收益改造影响结算精度 | 高 | 伞下比例制需按"该期已激活伞下用户投资额"实时汇总，大团队下 SQL 聚合量大，建议结算异步化（已用 ants）+ 按期预聚合缓存 |
| 算力矿机经济模型（3倍/300天） | 高 | 需与产品确认日产出公式与矿池总量（每日区块产出×0.3），参数全部配置化，上线前做数值仿真 |
| 手续费销毁依赖链支持 | 中 | 需确认 FIBO/KTO 链是否支持 burn；不支持则用黑洞地址 + 公开审计 |
| 多阶段多币种精度 | 中 | 各币种 decimal 精度不同（SymbolDictionary 已处理），新币种需补充精度与图标、价格源 |
| 轮次时限动态调整 | 低 | 需防"时限过短导致系统来不及结算"，加最小时限下限 |
| 存量代码 bug 需先修复 | 中 | 复用前先修复已发现问题：`Invite` 方法闭包表插错、`ops.SetLevel` 字段错误、`Withdraw` 流水类型笔误、`ChargePoint` 误用 Create 等（详见 crowd-master 解析报告第九节） |

## 六、结论

1. **可行**：crowd-master 与千万次玩法同构，复用率高（约 70%~80%），核心机制（期-轮模型、13% 静态、三进一出、动态分享、等级晋升、100%/50% 失败结算）已实现；
2. **核心改造 4 项**：团队收益改伞下比例制、爆仓补偿改算力折算、新增算力矿机三模式、新增手续费销毁；
3. **建议路径**：先参数化 → 玩法对齐（v1 内测）→ 算力矿机 → 经济闭环分阶段上线；
4. **前置动作**：先修复存量 bug，再启动复用改造。
